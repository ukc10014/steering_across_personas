# Experiment C — where in the OCT pipeline does the phenotype emerge?

**Status: SPEC, not yet run.** Written 2026-09-04, before any state is measured. Supersedes
nothing; it is the successor experiment to the reproduction gate
([GATE_REPORT_repro-123456.md](runs/oct/GATE_REPORT_repro-123456.md)) and the seed replication
([SEED2_REPORT.md](runs/oct/SEED2_REPORT.md)).

## The central question

> **Where in the OCT pipeline does the strong `impulsiveness` phenotype emerge: the DPO weight
> update, the DPO-generated introspection data, introspection SFT conditional on the DPO state,
> or the final PEFT adapter merge?**

This is a causal decomposition, not another adapter-generation exercise. The aim is **stage
localisation**, not the historical persona-ordering replication.

---

## 1. Model states

Six, not four. The brief specifies four; §1a explains why two more are needed to make the
comparison identify anything.

| state | construction | seed-1 artifact |
|---|---|---|
| `M_0` | unmodified `meta-llama/Llama-3.1-8B-Instruct` | — |
| `M_D` | base + DPO adapter, folded | `loras_repro/llama-distillation` → fold |
| `M_D+0.25S` | folded DPO model + SFT LoRA **at scale 0.25** | see §1a |
| `M_{D+S}` | folded DPO model + SFT LoRA **at scale 1.0** — the native post-SFT state | `loras_repro/llama-introspection` |
| `M_F` | base + `add_weighted_adapter([dpo,sft],[1.0,0.25],"linear")` | `loras_repro/llama-personas` |
| `M_S` | **SFT trained from `M_0`** on the same frozen corpus — §3 | must be trained |

Plus one labelled diagnostic, never a primary result:

| `M_0+A_S` | the existing SFT adapter applied **off-base** | cheap, already exists |

`M_F` is **not** `M_D + 0.25·A_S`. peft combines LoRA *factors*, so
`dW_F = dW_D + 0.25·dW_S + B_D A_S + B_S A_D`, and the cross terms were measured at **61.9%**
of `‖dW_F‖` on the real seed-1 pair — not a correction term, the dominant one.

### 1a. Why `M_D+0.25S` has to exist

As specified, `M_{D+S}` and `M_F` differ in **two** ways at once: the SFT contribution is
scaled 1.0 in one and 0.25 in the other, **and** `M_F` carries the cross terms. If `M_{D+S}`
comes out stronger, the brief's interpretation ("the final PEFT merge matters") is not
identified — it could be the down-weighting alone.

Adding `M_D + 0.25·A_S` separates them at negligible cost (`--lora-scale 0.25`, no training):

- `M_{D+S}` vs `M_D+0.25S` → the effect of **SFT dose**
- `M_D+0.25S` vs `M_F` → the effect of the **cross terms**, i.e. the merge operation itself

## 3. The SFT-from-base control — `impulsiveness_sft_from_base`

Train the introspection SFT LoRA starting from `M_0` instead of the folded DPO model, on the
**identical frozen corpus**. Every hyperparameter identical to the release-era run: rank 64,
alpha 128, LR 5e-5, warmup 0.1, batch 32 / micro 2, ZeRO-2, bf16, `max_len 3072`,
**`max_epochs 3`**, seed 123456. The *only* intended difference is `--pretrain`.

Named `impulsiveness_sft_from_base`, never `sft_only`: **the corpus was generated by the DPO
character model**, so this removes DPO from the weights being fine-tuned, not from the causal
history of the data. That distinction is the experiment's main interpretive hazard and the
name should carry it.

## 5. Dense SFT checkpoint curve

Fractional epochs `0, 0.1, 0.25, 0.5, 0.75, 1, 2, 3`. The corpus is 12,000 rows at global
batch 32 → **375 optimizer steps/epoch**, so checkpoints at steps
`0, 38, 94, 188, 281, 375, 750, 1125`.

**One continuous run with checkpoint saving.** Not eight short runs — that changes the
optimisation trajectory (LR schedule, warmup, momentum) and would confound stage with
trajectory.

### 5a. Implementation caveat, verified in the fork

The mechanism exists but the current runners do not use it. `train_sft.py` needs:

```
--save_steps 38 --save_hf_ckpt --disable_ds_ckpt --max_ckpt_num 32
```

- `--save_steps` alone writes **DeepSpeed ZeRO shards**, not a peft adapter. `--save_hf_ckpt`
  additionally calls `strategy.save_model`, which is what emits `adapter_model.safetensors`.
- `--disable_ds_ckpt` avoids writing full optimizer state at every point (large, unnecessary).
- **`--max_ckpt_num` defaults to 3 and the pruning loop deletes oldest subdirectories of
  `ckpt_path`.** Left at its default it would silently destroy the early checkpoints, which
  are the scientifically interesting ones. Must be raised.
- Steps are not exactly the fractional epochs; record the achieved step for each checkpoint
  rather than the nominal fraction.

### 5b. Two constructions per checkpoint

For each checkpoint `A_S(s)`:

1. **native sequential** — folded DPO model + `A_S(s)` at scale 1.0
2. **released-style merge** — `PEFTMerge(A_D, A_S(s))` applied to `M_0`

This is what separates *what SFT learns* from *what the merge contributes*.

## 8. Frozen inputs and provenance

- **The introspection corpus stays frozen throughout.** The point is to separate optimisation
  stages, not to vary data generation simultaneously.
- **Recorded explicitly:** the corpus contains character signal generated *downstream of DPO*.
  "SFT from base" removes DPO from the weights, not from the causal history of the data.
- **Nothing existing is overwritten.** `loras_repro`, `loras_repro_sft1ep`, `loras_seed2` and
  all their activations are immutable. Every new run and checkpoint gets a distinct name.
- `oct_provenance.py` at every stage: model revision, data sha256, seed, training config,
  **starting-model hash**, peft version.

### 8a. Two blockers found while writing this

1. **Seed 1's folded DPO model no longer exists.** `models/distilled_repro` was deleted in the
   2026-09-03 disk reclaim (recorded as regenerable at the time). `M_D` and `M_{D+S}` for
   seed 1 both need it. Regenerate with `fold_loras.py` from `loras_repro/llama-distillation`
   — ~3 min, deterministic, no retraining.
2. **Disk does not fit the plan as written.** CAA activations are 24 GB per arm. Six states +
   16 checkpoint arms ≈ **530 GB** against ~275 GB free.
   *Mitigation:* the geometry analyses read `_qcache/<arm>_L15_20.npz` (**1.57 GB**), not the
   raw `.pt` files. Extract → build qcache → **delete the 24 GB raw activations**, keeping
   peak at one arm. Cost: the raw per-layer tensors cannot be re-analysed at other layers
   without re-extraction (~25 min/arm). Recommended; flagged so it is a decision, not a
   silent deletion.

## 9. Hardware

- **Training (§3, §5, §7) needs a ≥80 GB card.** SFT at `max_len 3072` peaked at 78 GB on the
  RTX PRO 6000. The current pod is a **24 GB RTX 4090** and cannot run it. Shrinking
  `max_len`, micro-batch or ZeRO stage to fit would break "identical hyperparameters" and
  void the control.
- **Measurement runs fine on the 4090.** The logits pass used ~18 GB; extraction is forward
  passes at batch 16. Slower than Blackwell, not blocked.

So the experiment splits cleanly:

| runs now, on this 4090 | needs a new ≥80 GB pod |

| seed-2 stagewise comparison (§6) | |
